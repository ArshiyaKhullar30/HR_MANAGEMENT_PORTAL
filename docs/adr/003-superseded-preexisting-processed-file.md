# ADR 003 — `hr_performance_engagement_clean.csv` is superseded, not deleted

- **Status:** Accepted
- **Date:** 2026-08-28

## Context

`data/processed/hr_performance_engagement_clean.csv` (2,845 rows) existed in the
repository before this build. It is a partially-cleaned copy of the engagement
data: PII columns removed, an `Age` column added.

It is undocumented and unreproducible — there is no script that generates it, so
there is no way to know what rules produced it or to regenerate it if the source
changes.

## Decision

The file is **left in place but not used**. Nothing in the pipeline reads it.

It is superseded by `engagement_processed.parquet`, which is generated by
`hrai.cleaning.engagement`, checksummed into `data/processed/_manifest.json`, and
validated in strict mode after every run.

## Why not just delete it

It is the user's file and it predates this work. Superseding it is our call;
deleting it is not. It costs 640 KB and `data/processed/` is gitignored going
forward, so it will not accumulate.

## Differences worth noting

| | Pre-existing file | `engagement_processed` |
|---|--:|--:|
| Rows | 2,845 | 3,000 |
| Grain | unclear | one row per employee (documented, F5) |
| Duplicate IDs | present | resolved |
| Reproducible | no | yes, checksummed |
| Validated | no | strict Pandera contract |
| Training aggregates | no | yes |

The row-count difference is the clearest symptom: neither 3,150 (events) nor
3,000 (employees), so the grain it represents cannot be determined from the file
alone. That is precisely the problem an undocumented artifact creates.
